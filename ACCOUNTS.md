# Личный архив RRC

## Что работает

/account: отдельные аккаунты, вход по логину и паролю, восстановление по одноразовому личному коду, имя, контактный email, Telegram, 7 мерок тела, привычный размер, посадка, интересы и заметка. Поля профиля необязательны. Подборка вещей использует сохранённые интересы и текущую коллекцию; это простые правила по категориям, а не автоматический подбор точного размера.

Профили хранятся в SQLite на сервере (по умолчанию var/accounts.sqlite). Пароли защищены scrypt с индивидуальной солью. Коды восстановления и токены сессий хранятся только в виде хешей. Cookie HttpOnly / SameSite=Lax, в production также Secure; сессия 7 дней. Изменение профиля определяется сессией, а не присланным ID. Изменяющие запросы проверяют Origin. Вход/регистрация/восстановление/удаление ограничены 10 попытками в минуту на IP в одном процессе. Перед приложением должен быть доверенный reverse proxy, очищающий переданные клиентом X-Forwarded-* заголовки; порт 3000 не открывать наружу. Для нескольких серверов нужна другая база и общий limiter.

После регистрации или восстановления код показывается один раз. Клиент должен сохранить его отдельно. Восстановление заменяет код, пароль и закрывает прежние сессии. Восстановление по email не подключено; указанный email — контакт, не проверенный адрес. Команда не может читать пароль или личный код.

## Команда

/studio/clients открывает только профили клиентов, которые включили и сохранили «Разрешаю команде RRC видеть профиль». Нужен отдельный RRC_ACCOUNT_ADMIN_TOKEN (минимум 32 случайных символа). Не используйте короткий пароль или NEXT_PUBLIC_*; не передавайте токен клиентам. Токен вводится в форму и не сохраняется браузером. Страница выводит до 500 разрешённых профилей. Отключение разрешения исключает профиль из следующих ответов API; уже просмотренные данные не могут автоматически исчезнуть из памяти сотрудника.

Для production сгенерируйте токен на сервере и внесите в закрытый .env.production:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Локальный setup создаёт случайный токен в .env.local. Посмотреть его можно в этом файле на своём компьютере. В чат или публичный архив его не добавлять.

## Запуск

Нужен Node.js 24 LTS. npm run dev:lan запускает локальный сайт и кабинеты для проверки с телефона. Production-кабинеты требуют HTTPS: Secure cookie не предназначена для обычного HTTP на адресе компьютера в сети.

В production-шаблоне RRC_ACCOUNT_SIGNUPS=0. Вход уже зарегистрированных клиентов возможен, новые регистрации закрыты. До публичного открытия нужны полное ФИО ИП в сведениях оператора, рабочие контакты, подходящий сервер и настройка резервных копий/срока их хранения. Для серверов с персональными данными выбирайте размещение в России. Проверьте политику и согласие под фактическую работу бренда. После подготовки установите RRC_ACCOUNT_SIGNUPS=1 и перезапустите app. Это серверная настройка, пересборка фронтенда для неё не нужна.

Compose сохраняет /app/var в отдельном томе account_data. Обновление образа и обычный docker compose down не удаляют его. Не запускайте down -v и не удаляйте том без резервной копии. Одно приложение / один VPS; не размещайте SQLite на эфемерной файловой системе serverless.

## Данные и копии

Клиент может скачать свой профиль (без хешей и токенов) и удалить аккаунт, подтвердив пароль. Удаление очищает профиль и сессии из рабочей базы. Ранее созданные копии удаляйте по согласованному графику, например через 7 дней; после восстановления копии учитывайте удаления, сделанные после её создания. Не сохраняйте копии бесконечно и не публикуйте их.

Для согласованной SQLite-копии, включая активный WAL, используйте скрипт вместо простого копирования accounts.sqlite. На VPS:

```bash
docker compose --env-file .env.production exec app node scripts/backup-accounts.mjs /app/var/backups/accounts.sqlite
docker compose --env-file .env.production cp app:/app/var/backups/accounts.sqlite ./accounts-backup.sqlite
chmod 600 accounts-backup.sqlite
```

Скрипт требует новый путь: существующую копию не перезаписывает. Перенесите копию в защищённое место и задайте график. Копирование с VPS само по себе не является удалённым бэкапом. Проверяйте восстановление на отдельном временном сервере при выключенном приложении. Базу/копии/.env.local нельзя включать в ZIP или Git.

## Обновление кабинета

Кабинет называется «Личный кабинет». Паспорт посадки с мужской и женской 3D-скульптурами содержит 12 необязательных полей, включая обхват шеи, вес, обхваты руки, бедра и голени. 3D-манекен — инструкция, а не персональный скан. Старые профили получают новые пустые поля при чтении без изменения существующих значений. Внутренний круг использует отдельный серверный код и независимую сессию; выход из него не завершает вход в кабинет.
