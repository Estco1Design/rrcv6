# Оплата, производство и отслеживание RRC

Это план следующего этапа, не подключённая система заказов. Сейчас сайт подготавливает сообщение, которое покупатель самостоятельно отправляет @rrc_support.

## Оплата

Владелец подтвердил: продавец — ИП; PRE-ORDER оплачивается полностью. Рекомендована ЮKassa с согласованным решением для чеков. Кошелёк ЮMoney — другой сценарий переводов, не замена подключённому магазинному checkout.

До оплаты: выбор размера и подтверждение конкретных мерок/посадки, доставка, полный итог, согласие с опубликованными реальными условиями продавца. Свободная посадка — пожелание для согласования, не автоматически обещанный другой крой за ту же цену.

Сервер создаёт заказ в БД, пересчитывает суммы по каталогу и тарифу перевозчика, создаёт платёж идемпотентно. Заказ получает статус «Оплачен» только после серверной проверки API: сумма, валюта, идентификатор заказа и статус. Страница возврата из оплаты сама по себе не доказательство. Повторные уведомления не создают дубликат заказа или повторное уведомление клиенту.

Карта, включая Мир, и СБП показываются после включения соответствующих способов в платёжном аккаунте. Мир не нужно оформлять как отдельный дублирующий способ рядом с «Банковской картой». Наличные добавляются только для согласованного реального сценария, например личного получения; они не должны создавать впечатление оплаты предзаказа при получении без предоплаты.

Для ИП нужны: ФИО, ИНН, ОГРНИП, контакты, адреса для документов/возвратов, налоговый режим, информация о кассе/решении чеков. Налоговые реквизиты чека и работу с маркированными изделиями согласовать с бухгалтером/платёжным сервисом. Не публиковать шаблонные выдуманные реквизиты.

## Срок изготовления

До 14 рабочих дней. Дата подтверждённой оплаты в понедельник–пятницу считается днём 1; при оплате в выходные отсчёт с понедельника. Временная зона — Москва. До платежа размер и посадка уже согласованы, чтобы обещанный срок не зависел от бесконечного согласования после оплаты.

src/lib/production-calendar.ts считает это правило. Праздничные даты производства передаются отдельно; график ещё нужно предоставить. В интерфейсе оплаченного заказа дата окончания появится только после подключения реального платежа и календаря.

## Отслеживание

Статусы: «Ожидает оплаты» → «Оплачен» → «Крой» → «Пошив» → «Проверка» → «Готов к отправке» → «Передан перевозчику» → «Доставлен». Отдельно: «Требует согласования», «Отменён», «Возврат / возвращены деньги».

Платёжные состояния сообщает проверенный платёжный API; этапы производства меняет авторизованный сотрудник; доставка получает данные перевозчика. Этапы не переключаются таймером ради анимации. Показываем время фактического обновления, срок производства, трек и контакт поддержки. Возвраты могут быть частичными — модель заказа должна хранить суммы возвратов, а не только один флаг.

Покупателю — персональная ссылка с криптографически случайным токеном либо вход. По одному порядковому номеру заказа нельзя открывать имя, адрес и состав покупки постороннему. Токен хранится в БД в виде хеша, доступ ограничен, страница исключена из индексирования; персональные данные не выдаются в публичном API.

## Мини-игра после запуска

«Прошей RRC»: игрок проводит строчку по контуру букв, управление удержанием/касанием, результат — аккуратность и собранный логотип. Прогресс игры не влияет на реальный заказ и сроки. Игра загружается только после нажатия «Играть», не запускает анимацию в фоне, имеет паузу и облегчённый режим. Без обязательной игры, случайных обещаний скидки или скрытого сбора данных.

Приоритет: сначала реальные заказы, платежи/чеки, тариф доставки и корректные статусы; затем игра. Она не блокирует выпуск магазина.

## Проверка выпуска

Успешная и отменённая оплата; повторный webhook; несовпадение суммы; чек предоплаты и закрывающий чек по выбранной схеме; возврат; правильный срок буднего/выходного платежа; персональная ссылка не открывает чужой заказ; трек соответствует реальной накладной.
