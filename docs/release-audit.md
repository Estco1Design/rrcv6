# Аудит локальной версии RRC

Проверены Next.js / React / TypeScript, маршруты аккаунта, хранение SQLite, закрытый уровень и поисковые метаданные. Цель текущего этапа — локальная версия для проверки. Деплой и публичная эксплуатация в этот аудит не входят. Статический аудит дополнен локальными HTTP- и браузерными проверками. Он не подтверждает безопасность будущего хостинга, реальные Core Web Vitals или результаты индексации.

## Исправлено

- У `/shop`, `/about`, `/contacts`, `/delivery`, `/privacy-policy` и `/collections` появились отдельные title, description, canonical и Open Graph. Метаданные находятся в server layouts рядом с существующими client pages; клиентский код страниц не менялся.
- `src/app/collections/[slug]/page.tsx:5` формирует описание, canonical и Open Graph из существующих данных конкретной коллекции. Неизвестная коллекция получает noindex и по-прежнему возвращает notFound.
- У `/cart`, `/checkout`, `/favorites`, `/search` и `/admin` server layouts задают noindex. Эти маршруты разрешены в `src/app/robots.ts:4`, чтобы поисковый робот мог прочитать noindex; они не добавлены в sitemap. Robots.txt не является средством авторизации.
- В `next.config.mjs:5` настроены глобальные nosniff, X-Frame-Options DENY и Referrer-Policy. Строгая CSP остаётся отдельной задачей с проверкой совместимости Next.js и браузера.

## Авторизация и данные

Подтверждённого обхода серверной авторизации при чтении текущего кода не найдено. Это не эквивалент полноценному penetration test.

- Закрытый уровень доступен всем зарегистрированным пользователям с действующей сессией. `src/lib/account-session.ts:7` проверяет cookie через SQLite; `src/app/private/layout.tsx:9` перенаправляет гостя на вход. Наличие cookie само по себе не открывает доступ. Прежняя схема приглашений удалена и не относится к текущей модели доступа.
- `src/lib/account-db.ts:31` проверяет формат токена, его hash и срок действия в SQLite. Logout удаляет сессию (`:32`), восстановление пароля отзывает старые сессии (`:35`), удаление пользователя каскадно удаляет его сессии через foreign key (`:17`).
- `src/app/api/account/[action]/route.ts:23` проверяет Origin для POST. Cookies HttpOnly и SameSite=lax; Secure включается в production (`:9-10`). Для локального HTTP это ожидаемая конфигурация.
- SQL-запросы параметризованы; пароли защищены salted scrypt. Профили проходят Zod-проверку, токены и recovery-коды сохраняются как hashes. Пользователь может скачать данные и удалить аккаунт.
- `src/app/api/account/[action]/route.ts:16` требует bearer secret для доступа команды; `src/lib/account-db.ts:36` возвращает только профили с сохранённым shareWithTeam. Чувствительные ответы имеют no-store.
- Локальные секреты не включались в отчёт. `.env.local` не отслеживается Git. Значения production-конфигурации должны храниться в защищённых настройках будущего hosting.

## Условия будущего публичного выпуска

1. **Rate limiting и trusted proxy.** `src/lib/request-security.ts:14-25` хранит limiter в памяти процесса. По умолчанию используется общий бюджет прямых запросов: клиент не может сбросить его подменой forwarded header. Первый x-forwarded-for используется только при явном RRC_TRUST_PROXY=1. Перед публичным размещением этот режим следует включать только за прокси, заменяющим недостоверные forwarded headers; limiter должен учитывать все экземпляры. Без проверки инфраструктуры нельзя утверждать, что лимит защищает production.
2. **Лимит тела запроса.** `src/app/api/account/[action]/route.ts:26-30` проверяет Content-Length и длину уже прочитанного тела. Перед публичным доступом нужен лимит на стороне edge/proxy либо ограниченное чтение потока, чтобы не буферизовать чрезмерное тело без Content-Length.
3. **Постоянное хранение и backup.** `src/lib/account-db.ts:39` использует локальный SQLite-файл. Публичная среда должна иметь постоянный защищённый диск, проверенное восстановление и согласованный срок удаления backup. `src/app/privacy-policy/page.tsx` пока описывает график обслуживания без конкретного срока; срок следует указать только после определения реальной процедуры.
4. **Публичный origin.** `src/config/site.ts` использует NEXT_PUBLIC_SITE_URL для canonical, sitemap и OG. Перед будущей production-сборкой необходимо установить фактический HTTPS-домен; это значение встраивается при сборке. Локальная ссылка не является production-проверкой.
5. **Браузерная и live SEO проверка.** Нужны crawl реального адреса, HTTP-заголовки, мобильное отображение, загрузка ресурсов, JS-ошибки, noindex/canonical в HTML и Core Web Vitals. Оценка SEOmator и заявленный балл SEO здесь отсутствуют, потому что CLI-аудит опубликованного сайта не выполнялся.

## Границы проверки

Существующая база пользователей и данные заказов не менялись этим аудитом. Операционные условия выше — задачи будущего публичного выпуска, а не основание блокировать текущую локальную демонстрацию. Аудит фиксирует проверяемые свойства исходников и сохраняет неизвестные свойства hosting как неизвестные.

## Проверено в локальной production-сборке

- `npm run check`: линтер, TypeScript, 15 тестов и production build прошли.
- Playwright: регистрация, сохранение новых мерок после перезагрузки, 3D WebGL и кнопки вращения, клавиатура, 390px без горизонтального переполнения, fallback без WebGL, вход в закрытый уровень, отказ поддельной cookie, выход и удаление тестового аккаунта. Исключений браузера не было.
- `npm run start` теперь запускает standalone через `scripts/start-production.mjs`: статические ресурсы копируются в output, SQLite остаётся вне `.next`. Исходная фотография и оптимизированная версия возвращают HTTP 200 с ненулевым изображением.
- Начальный локальный crawl SEOmator выявил отсутствующий canonical главной, пустую HTML-оболочку каталога, отсутствие OG-изображений при переопределении metadata и lazy loading первой обложки коллекции. Эти проблемы исправлены. Начальный CLI-процесс прерван после записи отчёта; его балл не считается итоговым результатом.
- HTTP/HTTPS, localhost и несовпадение sitemap с локальным адресом в локальном crawl не являются подтверждёнными дефектами опубликованного сайта. Core Web Vitals не измерялись.

## Финальная локальная проверка

`npm run check` завершился с кодом 0. Сохранённый `tests/browser-smoke.py` также завершился успешно: дополнительно проверено вращение указателем, а не только кнопками. Живые HTTP-проверки подтвердили canonical главной, H1 каталога в исходном HTML, noindex корзины и заголовки DENY/nosniff.

SEOmator завершился с кодом 0, проверил 5 локальных URL по категориям core/images/perf/social без CWV. Отчёт находится в игнорируемой `qa/seo-final.json`. Локальный балл 86 не является оценкой публичного SEO. Оставшиеся сообщения: HTTPS-canonical против HTTP localhost; отсутствие canonical/OG URL у noindex-поиска; положение streaming metadata Next.js вне статического head, требующее оценки с учётом crawler; lazy-loading первой фотографии в каталоге — кандидат на дальнейшую оптимизацию LCP. Реальный LCP не измерялся. Никаких проверок или утверждений о публичном деплое не выполнено.
