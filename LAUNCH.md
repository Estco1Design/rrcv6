# RRC — предфинальная версия и выпуск

## Что уже готово

15 реальных моделей с утверждёнными ценами. Все пока PRE-ORDER, 100% предоплата; изготовление до 14 рабочих дней с даты подтверждённой оплаты в будни, доставка отдельно. CURRENT — №1, 4, 5, 11, 15; архив — остальные 10. Модель №10 удалена. Корзина, варианты, избранное, фильтры, RU/EN, галерея и ручная подготовка заявки работают. Эквайринг, база реальных заказов и отправка писем ещё не подключены.

## Фотографии

Финальный блок главной читает `public/images/home/editorial-mirror.jpg`.
Адрес в браузере: `/images/home/editorial-mirror.jpg`. Там уже стоит фотография, которая раньше повторялась в магазине. Для замены положите свою фотографию с тем же именем и форматом JPG. Рекомендуется 1600–2400 px по длинной стороне, без лишнего текста. После замены пересоберите сайт и обновите страницу без кэша. На хостинге пересоздайте только кэш изображений, если оптимизированный старый снимок ещё показывается.

Три разные обложки магазина задаются в `src/config/media.ts`: куртка с гербом для CURRENT, зипка с закрытым капюшоном для OBJECTS, архивное худи для ARCHIVE.

## Почему сайт мог проседать по FPS

Убраны реактивный полноэкранный градиент под указателем, 3D-слои всех карточек, полноэкранная SVG-текстура шума и непрерывное движение intro-фона. Убрано размытие фиксированной навигации. Альтернативное фото карточки загружается только при наведении мыши; на телефоне этот слой не создаётся. Уточнены responsive-размеры изображений. Параллакс и движение крупных надписей работают только на большом экране с мышью, при видимой вкладке и разрешённой анимации. Раскрытие главной и появления блоков сохранены.

Это не обещание постоянных 60 FPS на любом устройстве. Для окончательной проверки нужен повторный просмотр на вашем устройстве в production-режиме, особенно при включённом энергосбережении и аппаратном ускорении браузера.

## Посмотреть на телефоне без режима разработки

В папке проекта:

```bash
npm ci
npm run setup:local
npm run build
npm run preview:lan
```

Телефон и компьютер должны быть в одной Wi-Fi сети. Откройте адрес из терминала. Старый сервер остановите Ctrl+C перед новым запуском. Порт 3000 должен быть свободен. `dev:lan` остаётся для редактирования; это более тяжёлый режим разработки.

## Данные от владельца для выпуска

1. Поддержка по электронной почте. При необходимости — телефон, точные ссылки Instagram/TikTok/VK. Заказы направляются @rrc_support, канал — @richrussiancommunity, личные контакты команды опубликованы отдельно. Почта ещё не предоставлена.
2. Для каждой модели: реальные мерки готового изделия для размеров 1/2/3, состав, особенности ухода. Соответствия 1=S/M, 2=M/L, 3=L/XL пока ориентировочные. Все модели пока не в наличии; если есть готовые экземпляры — конкретный цвет, размер и количество.
3. Утверждено: 100% предоплата, в будни день подтверждённой оплаты — первый день, в выходные отсчёт с понедельника. Нужно уточнить праздничный график производства. Доставка по тарифу перевозчика, без бесплатного порога. Нужны индекс отправления, выбранный перевозчик/договор и фактические вес и габариты упакованных изделий (см. SHIPPING.md).
4. Продавец — ИП. Нужны ФИО ИП, ИНН, ОГРНИП, адрес для оформления документов/возвратов, рабочая почта и телефон, налоговый режим и сведения о кассе/решении для чеков. Условия возврата стандартных и индивидуальных изделий нужно сформулировать по фактической модели продажи и проверить до подключения оплаты.
5. Рекомендован магазин ЮKassa на подтверждённое ИП; подключение ещё не выполнено. Не присылайте секретные ключи в чат: они задаются только в серверном окружении. Для тестовой интеграции понадобятся магазин, API-доступ и выбранный способ формирования чеков.
6. После покупки VPS — его IP, ОС, доступ администратора по SSH через безопасный канал, доступ к DNS домена. Не размещайте пароли и приватные SSH-ключи в публичных файлах.

## Покупательский сценарий для следующего этапа

- Готовая вещь с известным размером и остатком: выбор варианта → доставка → оплата → подтверждение после проверки платежа сервером.
- PRE-ORDER: размер/мерки и срок до 14 рабочих дней показываются до оплаты. Утверждена полная предоплата. Если размер/посадка неизвестны, сначала согласование, затем индивидуальная ссылка на оплату.
- Сейчас работает этап запроса. Подготовка текста не отправляет заявку и не создаёт оплаченный заказ.

Для автоматического checkout нужны база заказов, серверный пересчёт цены из каталога, создание платежа с ключом идемпотентности, проверка суммы и статуса через API, обработка webhook, повторных уведомлений и возвратов. Ссылка «успешно» после возврата из сервиса сама по себе не подтверждает оплату. После интеграции проверяем тестовые успешный/отменённый платежи и чек; затем боевую оплату с разрешения владельца.

Кошелёк ЮMoney поддерживает формы переводов в кошелёк. Это отличается от интеграции магазина ЮKassa. Для checkout магазина и чеков предлагается сначала уточнить статус продавца и подходящее подключение ЮKassa. Срок подключения зависит от сервиса; выпуск витрины сегодня не означает, что эквайринг уже одобрен.

## Размещение на REG.RU

Нужен VPS/VDS с Node.js или Docker, а не тариф только для PHP/WordPress. Для сборки на сервере разумная стартовая конфигурация — 2 vCPU, 4 GB RAM и 20+ GB диска; это ориентир, а не гарантия нагрузки или конкретный тариф. Если уже есть другой тариф — сначала проверьте поддержку Node.js и постоянно работающего серверного процесса. Next.js содержит серверные маршруты, поэтому загрузка `public` через FTP не публикует весь сайт.

Подготовлены Dockerfile, compose.yaml и deploy/Caddyfile. Они запускают standalone Next.js за Caddy с HTTPS. Контейнер приложения не публикует порт 3000 наружу. Секреты не включены в сборку.

1. Купите VPS с Ubuntu и установите Docker Engine с Compose по официальной инструкции. Не ставьте вторую панель/прокси на уже занятые порты без проверки.
2. Создайте A-запись для `richrussiancommunity.com` на IP VPS. Для `www` используйте CNAME на основной домен или A на тот же IP. Если есть старая AAAA-запись на другой IPv6, исправьте её. Настройки почты MX/TXT не меняйте.
3. Откройте входящие 80/443 и доступ SSH. Загрузите распакованный проект в отдельную папку сервера.
4. В папке проекта:

```bash
cp deploy/production.env.example .env.production
chmod 600 .env.production
nano .env.production
```

@rrc_support уже задан. Заполните рабочую почту и ACME_EMAIL. Закрытый уровень использует сессию личного кабинета и доступен всем зарегистрированным участникам. Коды приглашения не используются.

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Если Node.js не установлен на сервере, сгенерируйте секрет на своём компьютере. Не сохраняйте его в Git.

5. Запустите:

```bash
docker compose --env-file .env.production up -d --build
docker compose --env-file .env.production ps
docker compose --env-file .env.production logs --tail=100 app proxy
```

Сертификат выдаётся, когда DNS указывает на VPS и порты доступны. Затем проверьте HTTPS, главную, обе языковые версии, картинки, корзину после перезагрузки и контакты с телефона через мобильный интернет. Обновление публичных контактов требует пересборки.

Для обновления исходников сохраните предыдущий архив, загрузите новую версию и повторите `up -d --build`. Не удаляйте `.env.production` и постоянные тома. `docker compose down -v` удаляет тома и здесь не требуется. Текущая схема может дать короткую паузу при обновлении; автоматический rollback и deployment без паузы ещё не настроены.

Без IP и доступа к приобретённому VPS эти конфигурации не являются фактической публикацией. Контейнеры и HTTPS необходимо проверить на сервере; локально проверяется production/standalone-сборка приложения.

Если тариф поддерживает только статические файлы/PHP, потребуется подходящий VPS/VDS или другое размещение с этими возможностями. Не загружать проект через FTP как статический сайт: так не заработают аккаунты и API.
